v1.3.0 — 2026-11-24

Release notes and downloads on GitHub

Added

  • The installer writes a one-sentence callgraph rule for Claude Code: bash install.sh now asks whether to write .claude/rules/callgraph.md, a single sentence telling the agent to navigate code with callgraph.sh locate (then the outline and --body) instead of Grep / Read. A project install writes it to <project>/.claude/rules/, a user install to ~/.claude/rules/. --rules writes it without asking (also the default when not run in a terminal), --no-rules skips it. An existing, different file is saved as callgraph.md.bak first; an identical one is left alone. Turn it off by deleting the file. The README also shows the equivalent CLAUDE.md lines for MCP users.
  • More ways to pick methods: file::Class.method and file::Class::method select the method of that class, and file::a,b,c selects several methods at once (the same as file::a ::b ::c).

Changed

  • The skill and the MCP texts are much shorter and say when to use callgraph: the SKILL.md description now says to use it before the first Grep / Read in a task that asks which file or function to change, where something is implemented or who calls what, followed by a short first-move recipe (locate with the task's names → outline of the top file → --body of one method → --grep for the callers). The instructions the MCP server sends on connect and the tool descriptions are trimmed to the same few lines.
  • --body respects the 400-line output limit: a longer body output keeps the first lines of each method (every == … header stays) and ends with a warning that points to --lines A-B for a range and --full for everything.
  • Module-level code is labelled as such in the outline: the __module__ entry is shown as module-level code L…-… instead of a method name; when its --body is cut, the warning suggests --lines A-B.

v1.2.0 — 2026-11-23

Release notes and downloads on GitHub

Added

  • trace <target>: the whole chain of a route or page in one short answer: callgraph.sh trace route::events.show prints, in at most 30 lines, the route (verb, URI, name, file and line), its middleware, the controller action, the FormRequest or inline rules (* = required), the models with their tables, the Inertia page with the props the controller passes, and the components the page uses. The target can be a route name (route::x), route:GET:/uri, a URI, Controller::method or Pages/X.vue. In a JS project a server route is shown with its client callers (regex routes are matched by path). An unknown target gives one line with up to 5 closest names. Over MCP it is the new trace tool.
  • --format routes reads JS / TS route tables: vue-router tables print as /chats/:id → src/pages/ChatPage.vue (chat), with nested children paths joined, lazy import() components resolved and redirect /x / redirect name:x shown. Hono, Express and itty server routes (app.get('/x', h), app.route('/p', sub) / app.use('/p', router) mounts, and a route("GET", /re/, handler) helper) print with their handler resolved through the imports, and with ← the client fetch / axios.* / ofetch / new WebSocket calls whose method and path match. A route name used in router.push({ name }), router.replace or <RouterLink :to="{ name }"> that no table defines is flagged ⚠ unknown route name 'x'; a client URL under a known server path that matches no server route is flagged ⚠ no server route: GET /api/x.
  • --format props: check what parents pass to Vue components: run on a folder or file, it lists ⚠ missing required prop 'title' Parent.vue L12 <Card>, ⚠ unknown prop 'colr' and ⚠ unknown slot 'foot'. It is lenient on purpose: v-model / v-model:x count as passed, kebab-case equals camelCase, nothing is "unknown" when the child uses $attrs / useAttrs / inheritAttrs / mixins or an imported or composed props type, nothing is "missing" when the parent spreads v-bind="obj", and standard HTML attributes (id, title, data-*, aria-*, form and input attributes, …) are never reported. With unplugin-vue-components, a tag without an import is matched to the one .vue file of that name, marked (auto).
  • More of the Vue component contract in the outline: slots (N) lists the <slot> outlets and exposes (N) the defineExpose names; provide('x') and inject('x') share one key, so --grep 'vue::provide:theme' shows both sides; defineProps<Props>() with an imported interface or type now lists its props. A Pinia defineStore('id', …) is a store block (actions and getters as methods, state keys as properties; setup stores: the returned functions), and useXStore().act() or const s = useXStore(); s.act() are calls to it, in the template too.
  • Tailwind 4 in stylesheets and --format classes: @utility classes and the utilities of @theme tokens (--color-brand-500 → bg-brand-500, text-brand-500, …) count as definitions, and the classes in @apply count as used. A used class whose token does not exist is flagged, for example theme: no such token text-brand-450 A.vue:9 (like text-brand-500, …); this is only reported when the project defines other brand-… tokens, never for Tailwind's own names or projects without @theme.
  • Blade: missing views, custom directives and @vite entries: the outline header flags an @include or <x-…> whose view does not exist (⚠ missing view: partials.gone (@include L4); static names only, package views like mail::x never), notes <x-dynamic-component> as a run-time target, and links a used Blade::directive / Blade::if to its registration (directives: @datetime → app/Providers/AppServiceProvider.php L12; the provider's outline lists the views using each). The files in @vite([...]) become import edges, so --grep resources/js/app.ts finds the template.
  • HTML entry files link to their scripts and stylesheets: <script src> and <link rel="stylesheet" href> show as import /src/main.ts lines and count as imports, so --grep src/main.ts finds index.html. External URLs are ignored.
  • React function components show their props in the outline: a component lists them as props (4): title*, size, onSave*, children (* = required). They are read from the first parameter (destructuring with defaults and ...rest), its TS type (inline, local or imported interface / type, extends, A & B), FC<Props>, memo(…) / forwardRef<El, Props>(…), X.propTypes (.isRequired) and X.defaultProps. A project hook (function useCart() that runs a React hook) is marked [hook] and its callers link to it; createContext, <X.Provider> / <X.Consumer> and useContext(X) share one key react::context:<file>::X, so --grep finds the provider and every consumer.
  • --format props checks React JSX uses too: it lists ⚠ missing required prop 'onSave' src/pages/Home.tsx L19 <Card> and ⚠ unknown prop 'colour'. It is conservative: a {...spread} skips the "missing" check, a ...rest, an HTMLAttributes-extending, union or unresolved props type skips the "unknown" check, and key, ref, children, className, style, data-* and aria-* are never unknown. Only components bound statically (same file or a direct import of a project file) are checked.
  • --format routes reads react-router: <Routes><Route path element /></Routes> trees (nested, index) and createBrowserRouter([…]) / createHashRouter / useRoutes([…]) arrays (element, Component, lazy, children) are listed, and a literal <Link to> / <NavLink> / <Navigate> / navigate('/x') path that no route matches is flagged ⚠ unknown route path '/x' (:param and * match). No warning without a route table or with a non-literal path.
  • Inertia pages written in React: in an @inertiajs/react project Inertia::render('Events/Show', …) resolves to Pages/Events/Show.tsx (or .jsx), the page props are those of its default-exported component, so --format inertia flags required props the controller never passes, and trace reaches the page and the components it imports.
  • gen react: writes React components, gen hook: custom hooks: react:Card>props(title:str,size?:'sm'|'md'='md')+ref:count:int=0+fn:inc():void{…}+jsx>div.card>h1{{ title }} with --write src/components/Card.tsx writes a function component: a typed props interface in .tsx, plain JS with JSDoc in .jsx, useState for ref:, an onSave callback prop for emits(save:int), useEffect for on:mounted{…} and Inertia useForm for form(a,b). Semicolons, indent and default vs named export follow the project's components. --into src/Card.tsx adds props, state, handlers and elements to an existing component; --replace is not available for .tsx / .jsx and says so. hook:useCart>ref:items:list<Item>=[]+fn:add(…){…} with --write src/hooks/useCart.ts writes a hook module. The MCP generate tool accepts both forms.
  • The laravel: preset writes React pages in Inertia + React projects: with @inertiajs/react it writes the Index, Create, Edit and Show pages (for example Pages/Fees/Create.tsx) as .tsx or .jsx, using the project's own input, label, error and button components (found by name and props, or set in .callgraph/gen.toml [components]). Translation calls are added only when existing pages already use a translation hook such as useTranslation().
  • Livewire components: class, view and uses linked, wire: names checked: a component class is tied to its Blade view (from render() or the default naming) and to where it is used (<livewire:counter>, @livewire('counter'), a full-page Route::get(…, Counter::class)). In the view, wire:model properties and wire:click / wire:submit methods are checked against the class and its Form objects, with ⚠ for a missing public method or property (static names only; the magic $refresh, $set, $toggle and $dispatch are never flagged). $this->dispatch('x'), Blade $dispatch('x'), #[On('x')] and v2 $listeners share the key livewire::event:x, so --grep finds both sender and listener. The new --format livewire view (also an MCP framework view) lists per component its view, uses, route, properties, actions, events, the validation rules from #[Validate] / rules() and the warnings, and ends with a line for names built at run time; <livewire:is :component="$x"> is noted there, not counted as a use. trace Counter and trace livewire:counter show the component's chain. Volt components are not supported yet.
  • Filament admin panels: a resource is shown with its $model, the getPages() pages with their URIs under the panel path, the form() fields (also inside Section, Grid and Tabs), the table() columns, filters, actions and bulk actions, and the getRelations() relation managers; standalone pages, widgets (with the models they query) and panel providers (id, path, resources) are listed too. The checks are conservative: a form field or table column that is not a column, fillable, cast, accessor or relation of the model is flagged only when the model's migration was found, and a relation manager or ->relationship('x') naming a relation the model lacks is flagged. The new --format filament view (also an MCP framework view) ends with a line for names built at run time; trace PostResource, trace filament:posts or the model name show the chain, and --grep filament::resource:Post finds the resource. Filament 4 Schema classes are not supported yet. The cache format changed again for Livewire and Filament; existing caches are rebuilt automatically.
  • More views say what they skipped: like --format forms, the routes, inertia and props views end with a line per reason, such as a route name built at run time, a page name that is not a literal or a v-bind object (? 2 skipped: <reason> (a.vue L3, b.vue L9, +N)), instead of silently leaving the item out.
  • next suggestions can learn from your own choices (opt-in, local only): with CALLGRAPH_NEXT_LEARN=1, on top of CALLGRAPH_NEXT=1 or --next, the suggestions are re-ordered from the accept / backtrack log that callgraph keeps in the project's .callgraph/results/ folder; nothing leaves the machine. Only the rule-based suggestions are re-ordered or dropped, never new ones invented. With little data the order is exactly the rule order; a kind of suggestion that is often followed by a backtrack moves down or is dropped, and when none is confident enough no next line is printed. Off by default; unset the variable to turn it off. The new callgraph next --eval replays the local log and reports how the learned order would have done against the rule order (top-1 hit rate, mean reciprocal rank, backtrack rate), with a note when there is too little data.
  • CALLGRAPH_COUNT=1 turns the anonymous daily count back on despite DO_NOT_TRACK: DO_NOT_TRACK is shared with other tools, so this explicit opt-in lets callgraph's daily count run anyway. CALLGRAPH_TELEMETRY=0, CALLGRAPH_UPDATE_CHECK=0 and CI still turn it off, CALLGRAPH_COUNT=0 keeps it off, and the opt-in telemetry is not affected (it stays off under DO_NOT_TRACK).

Changed

  • Vue emit keys belong to their component: an emit is now Card.vue::emit:save instead of vue::emit:save, and a parent's @save="h" / v-on:save on <Card> is an edge to the same key, so --grep 'Card.vue::emit:save' shows both the emitting code and the parents listening to it. Native DOM events and dynamic @[ev] get no edge. The cache format changed; existing caches are rebuilt automatically on the next run.
  • Vue template expressions are analysed like the script: calls in {{ }}, :x, @x, v-if and v-model get the same categories as in <script> (a const store = useX() binding, imports, built-ins), inline handlers like @click="a(); b++" are read, optional-chain calls (a?.b()) are found and dynamic calls (handlers[name]()) are marked. v-for items and slot props are local names, so item.open() is no longer listed as a call. An expression that cannot be parsed falls back to the previous name-based reading.
  • useContext(X) points to the context, not to React: it is now an edge to react::context:<file>::X instead of react::useContext. The cache format changed again; existing caches are rebuilt automatically.

v1.1.1 — 2026-11-18

Release notes and downloads on GitHub

Added

  • A short impact view with --compact: --grep … --depth N --compact prints the callers level by level, one line per file (path: A() L12, B() L40 ← target, wrapped at about 160 characters), so a wide impact analysis stays short. Route registrations show their actual code, for example L5 Route::delete('songs', [SongController::class, 'destroy'])->name('songs.destroy'). When all entries of a file point to the same target, ← target is printed once, right after the file name. Over MCP it is the find_callers parameter compact: true.
  • locate understands a plain sentence: write the task as you would say it. Common English and Hungarian filler words (hol, a, az, hogy, …) are ignored and listed as ignored: … in the header; quoted phrases are still searched as phrases. Matches in translation files (Laravel lang files, JSON/TS dictionaries, .po / .xliff) count much less, so a code file whose name or symbol matches ranks above them. When most words match only UI text, the header suggests adding the English code name; when nothing matches in code, it says so (no code match) and keeps the list, which helps if you are looking for a UI label.

Changed

  • --grep / find_callers finds exactly the name you give: execute no longer matches executeCommand, and store (a method) no longer matches the class Store. A class name still finds its qualified calls (SongService matches App\Services\SongService::x). For the old "contains" search use a regex, for example '.*execute.*'; regex and Type::method patterns stay case-insensitive.
  • Cleaner call lists for Go and Rust: in Go outlines a call on the method's own object shows as a plain method name (like PHP $this->x), and other calls as Type::method. In Rust, a call through nested fields (self.a.b.m()) is no longer listed as a certain caller in --depth; it appears only with --guess.
  • update / callgraph.sh update [--dev] reminds you to reconnect MCP: after a successful update it prints a note that a running MCP server keeps the old version until you reconnect it (Claude Code: /mcp, then Reconnect).

Fixed

  • --grep Type::method and --depth N find callers that were missed: Python calls through self. / cls. and Go calls on the method's own object, typed parameters, typed local variables (also multi-value assignments) and method chains. Before, the result could say that nothing calls the method, or the level-2 list in Python could come back empty.
  • --depth lists every route to an action: a routes file with several [Controller::class, 'method'] routes showed only the first at level 2, and two routes to the same action showed only one; now each is listed. --grep 'Ctrl::m' --depth N on the controller action itself lists its route registrations at level 1; before, it said there were no callers. When a short Ctrl::method pattern matches same-named classes in several namespaces, each level-1 route row names its fully-qualified target, in the normal and --compact views.

v1.1.0 — 2026-11-17

Release notes and downloads on GitHub

Added

  • Blade templates (.blade.php) are analysed as their own language (before, the result was empty): one view per file, named like admin.users.index, with sections, pushes and slots as line ranges; @extends / @include / @each / <x-…> / <livewire:…> resolve to the view files, so the callers of a layout list the views extending it; @props show as properties; PHP inside {{ }}, {!! !!}, @php and directive arguments is analysed; @if / @foreach … appear as control flow; route('x') links to the Laravel route (→ POST /users · Controller@method, unknown names are flagged); __() / @lang take part in the i18n check; and a "rendered by" line lists the view('…') calls in controllers.
  • MCP undo tool: restores the last change made by generate or rename — one file when a file is given, otherwise the whole last group of changes. The history is multi-step: each call steps one change further back (before, two undos in a row toggled the last change). Like generate and rename, it only exists when the server runs with --generate / CALLGRAPH_GENERATE=1, and it is marked readOnlyHint: false.
  • rename term <old> <new>: rename a whole concept in every spelling: rename term post article changes the word in PHP, JS, TS and Vue code wherever it appears as a whole word, keeping the case and plural: Post / post / posts, post_id, StorePostRequest, /posts/{post}, admin.posts.index, Posts/Index.vue. Plurals with -s, -es and -ies are formed automatically; an irregular one is given as person/people. Files whose path contains the word are moved, and if the migrations create tables (also pivot tables) or *_id columns with the word, a new reversible migration renames them (rename_post_to_article); existing migrations are not touched. Skipped: all-caps words (POST), HTTP-verb calls (->post(, Route::post(, postJson(), vendor and node_modules. A quoted word in value position that may be an HTTP verb ('method' => 'post') is only flagged, not changed. --dry shows the whole plan (files moved, changes per file, flagged strings, the migration), and one undo reverts everything, including the new migration. Over MCP it is the term kind of the rename tool.
  • gen previews and more placement options: with --into / --replace, --dry first prints where the code would go, e.g. → app/Pay.php::Pay after charge (L41) or → f.vue: script L12-14, and --diff shows a --replace as a short unified diff without writing anything. For PHP --into, --before <method> and --at L<n> place the code before a method or at a line (an --at outside the class body, e.g. on the { line, is rejected upfront with the body's line range), and --upsert turns an --into of an existing method into a replace (with --expect, the expectation is checked when the member already exists). Vue --into file.vue::template#id (or ::#id, ::.class) appends inside that template element, the expression being read as template markup, and --replace file.vue::script / ::template / ::style replaces the whole content of that section (the tags stay), with no line range that can go stale. The MCP generate tool got before, at, upsert and diff.
  • gen PHP: traits, anonymous classes and Laravel class names: use:HasFactory,Notifiable under a type writes use HasFactory, Notifiable; inside the class body (c:Post<Model> > use:HasFactory + +comments():HasMany{…}). a:<Migration> > +up():void{…} writes an anonymous class, return new class extends Migration { … };, as in Laravel migrations. In a Laravel project (laravel/framework in composer.json) common framework classes such as Model, Schema, Blueprint, Route, Request, Rule, Builder, HasMany or RefreshDatabase are imported without use:; names that exist in several packages (e.g. Response) still need use:.
  • gen PHP statements outside a class: php{ … } and raw{ … }: php{ Route::get('/posts', [PostController::class, 'index']); } writes plain PHP code. With --write routes/x.php it creates the file (adding <?php and the imports), with --into routes/web.php it appends to the end of the file or goes to --at L<n> / --after L<n>, and with --replace bootstrap/app.php:L14-L16 it replaces that line range or a method. The code takes the indentation of the line it goes at or replaces, and an empty php{} with --replace file:La-Lb deletes the lines. raw{ … } writes the text exactly as given, e.g. a Blade view with --write resources/views/app.blade.php; Blade files are not PHP-syntax-checked.
  • Vue props from interfaces, defaults and defineModel: defineProps<Props>() now resolves a local interface or type alias (including extends and A & B); withDefaults defaults are shown as type $name = default and the prop is not marked required; defineModel appears as model: in the outline and as a model section in --format api. A type-only defineEmits now shows its real line.
  • Kotlin support (.kt, .kts): classes, data/sealed/enum classes, objects and companion objects, interfaces, top-level and extension functions, suspend and @Composable functions, properties (including by lazy and by viewModels()), calls with receiver type resolution, ::ref / Type::name references and control flow. Categories cover Compose (views, modifiers, API), coroutines, Android and the Kotlin standard library; *.gradle.kts files are marked as Gradle build scripts. hiltViewModel(), viewModel() and by viewModels() are injection edges, and calls on the view model resolve to its type. Hilt @Inject constructor, @Provides and @Binds show what is injected and which method provides a type. NavHost composable("route") { Screen() } and navController.navigate("…") are navigation edges (type-safe routes too, navigate(Detail(…)) / composable<Detail>), also when the NavHost is in another file. Callers of an interface method and of its implementations see each other. Android projects get a profile (ui / view model / data / domain / di layers; *.gradle.kts is not counted as app code), and Kotlin appears in the usage statistics. !! does not hide the receiver of a call, *Test.kt files and androidTest folders count as tests in locate, and method bodies are filtered correctly (comments, raw strings).
  • Swift callbacks, protocols and navigation: a method reference passed as a callback argument (Composer(onSend: vm.send)) is a call of that method. A closure stored in a callback property (socket.onFrame = { … }) is linked to where the property is invoked. Callers of a protocol method and of its implementations see each other (via), and a conformance declared in an extension counts. .environment(store) / .environmentObject are injection edges, and views built in navigationDestination, sheet, fullScreenCover, popover or NavigationLink are navigation edges. Receiver types are taken from @State, @Bindable, let x: T, @Environment(T.self) and parameters. A reference passed positionally (.onChange(of: x, vm.changed)) or via #selector(…) is a reference call; key paths are not calls. SwiftData @Query var items: [Item] is a model edge and modelContext calls are categorized. Each view in a navigationDestination { switch … } is a navigation edge, generic views (List<Item>(…)) count as component uses, and actor methods resolve. A call through a property chain that spans files (self.store.session.user.load()) resolves to the method of the last property's type. The method that invokes a stored closure (onFrame?(…)) is listed as a direct caller of the closure's callees, as via <Type>::<property>; these callers and callers resolved across files (Kotlin routes, Swift property chains, Rust trait bounds) are shown at the first level of the callers list, under "called through a stored closure or resolved across files".
  • callgraph mcp --allow <dir>: lets the MCP server read an extra folder, e.g. a sibling ../android. Repeat the flag or set CALLGRAPH_MCP_ALLOW; by default the server stays restricted to the project root.
  • Rust: function references and more receiver types: a function or method passed as a value (.map(Self::parse), .and_then(Foo::new), .map(helper)) is a call. Receivers typed by a generic bound (T: Trait, where) or by a method's return type (self.make()?, Type::open().unwrap()) are resolved. Loop variables (for b in self.bars), if let Some(x) / while let / match Some(x) bindings and iterator-closure parameters (items.iter().map(|x| x.name())) get their element type, so their method calls resolve; with T: A + B the trait that declares the method is used, also when the traits are declared in other files. #[test] / #[tokio::test] functions and #[cfg(test)] modules are marked as tests, Some / Ok / Err / Box::new / Default::default no longer clutter the call list, and calls of a local closure are marked dynamic. Callers of a trait method and of its implementations see each other in both directions (via).
  • JS/TS: functions passed as values are callers: a function handed over as a call or new argument, an array element or an object property value (also shorthand), e.g. the handler in a route table guarded(api.listX), is a reference edge marked (ref). It shows in callers lists, counts for --depth / impact, and the function no longer looks like it has no callers. This covers functions of the same file, local imports, object-literal methods and members of a namespace import (import * as api); package functions are not counted.
  • More JS/TS imports resolve to files: tsconfig extends (a string or an array, also chained) and references are followed, a paths entry may have several targets and a * in the middle (the longest matching prefix wins), and resolve.alias in vite.config.* / vitest.config.* is read (an object or [{find, replacement}], with fileURLToPath(new URL(…)) or path.resolve(__dirname, …)). An alias is used only if its target exists. So imports like @shared/api or @kit/… find their callers and deps no longer reports them as missing packages. Imports without an extension also find .tsx, .jsx, .mts, .cjs, .cts files and index.vue / index.tsx / index.jsx / index.mjs, and ./a.js in a TypeScript project resolves to a.ts. Import resolution is faster too: each folder is listed once instead of checking every candidate file.
  • PHP: X::class references: X::class, a callable pair [X::class, 'method'] (X::method) and an invokable controller in Route::get($uri, X::class) (X::__invoke) are reference edges marked (ref), resolved through use and the namespace. --grep X, locate X and --depth now also find the routes, config entries and bindings that name the class.
  • PHP: calls resolve through docblock types: a variable or property typed only in a docblock now leads to the right method, so its callers are found (before, --grep 'Model::method' could find no callers there). Read: @mixin on a class (Laravel API resources: $this->m() that the resource does not define goes to the model's m, except the resource's own helpers), @var above an assignment or a foreach (also element types such as Collection<Post> or Post[]), @property / @property-read, @param of an untyped parameter, @return and @method. Native type declarations win, and only a single unambiguous class is used (?Post / Post|null count).
  • Full Laravel route table with --format routes: on a Laravel project every route is one row with its method, full URI, action, name=, [middleware] and file:line, with the prefix, name and middleware of groups inherited through nesting. The same table feeds --format ziggy, inertia and forms. Routes generated in a loop from a literal config array (foreach (config('catalogue.pages') as $name => $page) Route::get($page['uri'], …)->name($name)) are expanded into real rows and are no longer dynamic: ziggy knows their names, and inertia knows their pages (a page component named in the config that does not exist is flagged). The stored route data is rebuilt once, quietly.

  • Notes on files and methods (pilot): callgraph note add <file>[::<method>] "<text>" (also callgraph.sh note …) attaches a short note, stored outside the source in <project>/.callgraph/notes.jsonl (git-ignored) with the date and time (UTC). The outline shows it under the file header or the method (📝 2026-11-05 20:27 · text, newest first, at most 3), --body above the method source. note list [<path>] lists them (with [orphaned] when the method is gone), note rm <id> deletes one, and show <dir> --notes <pattern> searches them. The anchor is the method name, not a line number. MCP: a new read-only notes tool (there is no write tool). Without notes the output is unchanged. Details: docs/NOTES.md.
  • TypeScript: calls through typed objects and interfaces. callgraph now works out which class a TS method call goes to when the type is written down: a typed parameter (repo: Repo), a typed class property (private repo: Repo, also constructor(private repo: Repo)), this.repo = new Repo() or const x = new Repo(). So this.repo.find() shows up as Repo::find, and --grep 'Repo::find' finds it. Classes record their implements, and TS interfaces (interface X extends Y) appear in the map, so searching PlaylistResolver::getPlayables also finds calls made through its Resolver interface, marked via Resolver (in --depth and callers too). When the type is unclear (no type, any, a union like Repo | null, a generic T, or different values in the same function) the call stays as before.
  • --const lists re-exports: besides references and definitions, --const NAME now shows where a name is passed on, marked [re-export]: Rust pub use state::{CheckState, STATE_FILE}; / pub(crate) use …, JS / TS export { NAME } from './x' / export { NAME }, PHP use const App\NAME;.

Fixed

  • --grep <pattern> --body prints the source of the caller methods again (the option was ignored).
  • MCP method_body: method may be a single name as a plain string as well as a list (some clients send "method": "parse", which used to fail with an "expected a sequence" error).

Fixed

  • JS/TS: no more doubled methods when a class is named like its file (PlaylistResolver.ts with class PlaylistResolver): the class's methods were listed twice, once under the file's module entry and once under the class. Now class members appear only under the class and top-level functions only under the module.

v0.2.0 — 2026-11-05

Release notes and downloads on GitHub

Added

  • Background update check: at most once a day callgraph.sh checks GitHub in a detached background process (never slows a query down). If a newer release exists, the output ends with one line, once a day: ℹ callgraph X is available (installed: Y) — update: bash …/callgraph.sh update. Claude Code tells the user and offers the update; it never updates on its own. Opt out with CALLGRAPH_UPDATE_CHECK=0; off in CI.
  • Bug reporting via GitHub: bilingual issue forms (bug report, idea / feedback), a private security report link and SECURITY.md. Error messages now point to the bug form; feedback.sh show <error-id> prints the details to paste.
  • Release checksums: every release has a SHA256SUMS asset (sha256sum format, all assets). update verifies the downloaded zip's SHA-256 before installing and installs nothing on a mismatch; a release without SHA256SUMS (v0.1.0) is refused unless --insecure-skip-checksum is given. update --from <zip> checks --sha256 <hex> or a SHA256SUMS next to the zip, otherwise it warns in one line and installs.
  • MCP server mode: callgraph mcp runs a Model Context Protocol server on stdio (official Rust SDK rmcp), so Claude Desktop, Cursor, VS Code or any MCP client can use callgraph. Tools: outline, method_body, find_callers, search, framework_view, projects — the same compact text and output cap as the CLI. Read-only, no network, paths confined to the project root. The skill / CLI usage is unchanged. Setup recipes: docs/MCP.md.
  • See how something is called: "where is it called" results (--grep, and every level of --depth) now show the call's own source line next to its line number, e.g. L25 │ $this->repo->find($id) — no extra --body call needed just to see the arguments.
  • Calls through interfaces and traits: searching a class method (--grep 'PlaylistResolver::getPlayables') also finds the calls made through its interface, abstract parent or trait (and, the other way round, through subclasses that don't override it). These are marked, e.g. L14 via Resolver │ …; --depth follows them to the next level, and callers adds a "via" field. Works where the call's receiver type is known (PHP: typed properties and other resolved receivers; Rust: Type::method calls); JS/TS interfaces and Swift protocols are not tracked yet.
  • Rust: smarter method calls. For x.load() callgraph now works out the type of x in the simple cases (parameter type, let x = Repo::new(), Repo { … }, self, a field of your own struct like self.repo), so the call shows up as Repo::load and "who calls Repo::load?" finds it. When the type can't be worked out, the call is kept as ?::load and a Repo::load search still lists it, marked as uncertain — instead of silently missing it.
  • Rust constants: --const now finds Rust const / static items — where they are defined and where they are used (also Type::CONST).
  • JS / TS object methods: functions inside an object literal (const api = { fetch() {}, save: () => {} }, or a plain export default { … }) are listed as separate methods (api.fetch) with their line ranges, and calls to them are found.

Changed

  • Shorter result lists: when the project root would repeat on many lines (--grep, --depth, --strings, --const, folder outlines, framework views…), the first line is now root: /abs/path/to/project and every path after it is relative to that root. Outputs with a single path, and the machine formats (json, mermaid, dot, callers), are unchanged.
  • SKILL.md now recommends finding callers by name (--grep '(^|::|\.|->)name$'), which also catches inherited, trait and unknown-receiver calls; Type::method is for narrowing a common name. It also explains the new search output (root: line, L<n> │ code, via, ?::) and the new Rust / JS options.
  • --const also lists the matching constant definitions (marked [definition]), not only the references.

Fixed

  • Windows: the project root is printed as C:\… instead of \\?\C:\… in search output.
  • A bare method selector also finds an object-literal method: store.ts::updateSongs selects playableStore.updateSongs.
  • --grep … --depth: from level 2 on, callers are searched in the whole project (from the project root), not only in the folders of the level-1 matches — callers in other folders were missed.
  • Rust --format api now lists the pub fn methods of impl blocks (and trait implementations), the pub constants and fields — before, it showed no public methods for Rust types.
  • --strings now finds texts inside Vue template expressions ({{ … }}, :title="…", @click="…") and in Rust const / static values, including byte strings (b"…").
  • SCSS: @mixin / @function parameters ($color: t.$brand, …) and @include keyword arguments were listed as constants; now only $var: value; declarations are (the parameters stay the mixin's params).
  • update --check now also records its result in update-check.json, so the daily background check does not repeat it and a newer version found manually shows up in the notice.
